Frequently Answered Questions

Deep technical guidance on integrating Orbit into your enterprise vector architectures.

What vector distance metrics does Orbit natively support?

Orbit supports Cosine Similarity, Euclidean (L2) Distance, Dot Product (Inner Product), and Manhattan (L1) Distance. All distance computations are hardware-accelerated using AVX-512 and ARM NEON SIMD instruction sets for zero instruction overhead.

How does Orbit handle dynamic real-time insertions without locking queries?

Orbit uses an LSM-tree (Log-Structured Merge-Tree) architecture adapted for graphs. Incoming vectors are appended to an immutable in-memory memtable (WAL-backed). As queries execute, they merge search frontiers across immutable segment levels concurrently via lock-free epoch reclamation.

What is the latency difference between uncompressed vectors and PQ8?

With Product Quantization (PQ8), memory bandwidth requirements decrease by approximately 75%. In our benchmarks, PQ8 actually results in 22% faster query latency due to significantly higher L3 CPU cache residency, with less than 0.8% variance in Top-10 recall accuracy.

Can I run Orbit on my own cloud VPC or on-premise infrastructure?

Yes. Enterprise customers can deploy the Orbit Distributed Daemon either via our managed control plane inside their AWS/GCP VPC or via standalone Helm charts on bare-metal Kubernetes clusters with complete data sovereignty guarantees.

Which programming language SDKs are officially maintained?

We maintain official high-performance gRPC and REST client libraries for TypeScript/JavaScript (Node.js & Edge Runtimes), Python (asyncio), Go, Rust, and Java. Community-supported drivers exist for C# and Elixir.
